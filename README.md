# 엔지니어링 과제

## 이 과제에 대하여

이 과제는 **코드를 작성하는 것이 아니라, 코드 작성을 위한 설계 문서를 작성**하는 과제입니다.

각 문제에 대해 "어떻게 구현할 것인지"를 `.md` 파일로 정리해 주세요. 구현 코드는 필요 없습니다. 대신, 실제로 이 설계 문서를 다른 엔지니어에게 건네면 구현을 시작할 수 있을 정도의 구체성을 기대합니다.

## 서비스 소개

이 과제는 **웹 추적 서비스**를 배경으로 합니다. 아래 설명을 읽고 과제를 진행해 주세요.

### 웹 추적 서비스란?

기업이 온라인 광고를 집행하면, 광고를 본 사람 중 일부가 광고를 클릭하여 기업의 웹사이트에 방문합니다. 기업 입장에서는 "어떤 광고가 실제로 효과가 있었는지" 알고 싶습니다.

웹 추적 서비스는 이 문제를 해결합니다:

1. 기업(고객사)의 웹사이트에 JavaScript 코드 한 줄을 설치합니다
2. 이 코드(SDK)가 방문자의 행동을 이벤트로 기록합니다
3. 각 방문자가 "어떤 광고를 보고 왔는지" 판별합니다
4. 고객사는 대시보드에서 광고별 성과를 확인합니다

### 주요 개념

**이벤트**: 방문자의 행동 하나하나를 기록한 것입니다. 종류는 다음과 같습니다:

| 이벤트 타입   | 설명            | 예시                                         |
| ------------- | --------------- | -------------------------------------------- |
| `pageview`    | 페이지를 조회   | 방문자가 상품 상세 페이지를 열었다           |
| `interaction` | 요소와 상호작용 | 클릭, 외부 링크 이동, 이탈 시도, 미디어 재생 |
| `form`        | 폼 관련 행동    | 상담 신청 폼 제출, 작성 중 이탈              |
| `lifecycle`   | 시스템 이벤트   | 세션 시작, 디바이스 식별 완료                |

각 이벤트에는 SDK가 생성한 고유 ID(`event_id`)가 포함되어 있습니다.

**세션(Session)**: 한 번의 방문을 의미합니다. 방문자가 웹사이트에 도착해서 떠날 때까지 발생하는 이벤트들의 묶음입니다.

**방문자(Visitor)**: 고유하게 식별된 사람입니다. 한 방문자가 여러 번 방문하면 여러 세션이 생깁니다. 방문자 식별에는 디바이스 지문(Fingerprint) 기술을 사용하며, 정확도는 100%가 아닙니다.

**어트리뷰션(Attribution)**: "이 방문자가 어떤 광고 채널에서 왔는지" 판별하는 것입니다. 아래에서 자세히 설명합니다.

### 어트리뷰션이란?

방문자가 광고를 클릭하여 웹사이트에 도착하면, URL에 광고 플랫폼이 붙인 파라미터가 포함됩니다:

```
https://example.com/landing?utm_source=facebook&utm_medium=cpc&fbclid=AbC123xYz
```

이 파라미터들을 분석하면 방문자가 어디서 왔는지 알 수 있습니다:

| 파라미터     | 의미                             | 누가 붙이나             |
| ------------ | -------------------------------- | ----------------------- |
| `fbclid`     | Meta(Facebook) 광고 클릭 ID      | 광고 플랫폼이 자동 발급 |
| `gclid`      | Google 광고 클릭 ID              | 광고 플랫폼이 자동 발급 |
| `ttclid`     | TikTok 광고 클릭 ID              | 광고 플랫폼이 자동 발급 |
| `utm_source` | 유입 소스 (예: facebook, naver)  | 마케터가 수동 설정      |
| `utm_medium` | 유입 매체 (예: cpc, blog, email) | 마케터가 수동 설정      |
| `referrer`   | 이전 페이지 도메인               | 브라우저가 자동 전달    |

이 정보들의 **신뢰도는 서로 다릅니다**:

- Click ID (`fbclid`, `gclid` 등): 광고 플랫폼이 직접 발급하므로 가장 정확
- UTM 파라미터: 마케터가 수동으로 설정하므로 실수가 있을 수 있음
- Referrer: 브라우저 설정에 따라 누락될 수 있음

어트리뷰션은 이 정보들을 종합하여 "이 방문자는 Meta 유료 광고에서 왔다", "Google 자연검색에서 왔다" 등을 판별하는 과정입니다. **고객사마다 다른 판별 규칙**을 가지고 있습니다.

### 현재 아키텍처

```
고객사 웹사이트
    │
    ▼
[JavaScript SDK] ── 방문자 행동을 이벤트로 수집
    │
    ▼
[API 서버] ── 이벤트 수신, 어트리뷰션 판별, DB 저장 (약 1,000줄의 로직)
    │
    ▼
[관계형 DB] ── 이벤트 저장 + 대시보드 조회 (단일 DB)
    │
    ▼
[대시보드] ── 고객사가 채널별 성과를 확인
```

- 여러 고객사가 하나의 시스템을 공유합니다 (멀티 테넌트). 고객사 간 데이터는 완전히 격리됩니다.
- API 서버는 이벤트를 수신할 때마다 어트리뷰션 판별, 세션 관리, DB 저장을 **동기로** 처리합니다.
- 단일 관계형 DB에 이벤트 저장과 대시보드 조회가 모두 이루어집니다.
- SDK는 바닐라 JavaScript로 작성되어 있으며, 프레임워크 의존 없이 어떤 웹사이트에서든 동작합니다.

- **결과물 형식**: 모든 결과물은 `.md` 파일로 작성. 형식과 구성은 자유입니다. 문서에 무엇을 포함할지도 본인이 판단해 주세요.

- **평가 기준**: 정답 여부보다 **사고 과정과 판단의 질**을 봅니다.
- **질문**: 과제 내용에 대한 질문은 자유롭게 해 주세요
